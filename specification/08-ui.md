# 08 — UI

Desktop-first (min 1280 px) but usable at 768 px; report viewer works on tablets.
Design: shadcn/ui, light + dark theme (dark default, matching the prototype report palette:
background `#0f1117`, panels `#1a1f2e`, accent indigo `#818cf8`, status colours from prototype chips).

## 2. Layout

Left sidebar: project switcher (search), project nav (Overview, Sitemap, Runs, Comparisons,
Ignore rules, Storage, Settings), admin section. Top bar: breadcrumbs, active-job indicator
(spinner with count, popover listing running jobs with progress), user menu.

## 3. Key screens

**Project overview** — cards: Baseline (label, date, items), Last run (status, progress if
running), Last comparison (chips + review progress), Quick actions: *Fetch sitemap*, *New run*,
*Compare latest with baseline*. Recent activity (audit, last 10).

**Run detail** — header with label, status badge, note, actions. Progress bar segmented per
viewport. Tabs: *Items* (virtualised table, thumbnail 80 px), *Failures* (grouped by error
message), *Settings used* (frozen JSON pretty-printed).

**Report** — header: before ↔ after labels (links), status, *Share*, *Download HTML*,
*Re-diff*, *Promote to baseline*. Summary chips (clickable filters). Viewport tabs (All, desktop,
mobile…). Left: list of items (URL path, % badge, review dot). Right: item viewer (modes per
F-CMP-4) with review toolbar (Approve / Reject / Ignore / note / ignore-rule shortcuts).
Sections below list: Files, Redirected, New, Missing. Empty state: "✅ No visual differences
detected above the X % threshold" (prototype wording).

**Item viewer** — v1 loads the full PNGs lazily (`loading=lazy`, no thumbnails generated);
items captured with `truncated=true` show a "truncated at N px" ribbon. Region drawing
tool for ignore region uses image pixel coordinates (account for zoom).

**Public share** — Report without review controls, settings, nav; banner "Shared read-only
report — expires <date>".

## 4. States & feedback

* Every async action: optimistic disable + toast on success/error; errors show server message.
* Long jobs never block the UI; user can navigate away; global job indicator persists.
* Empty states with a primary action (e.g. "No runs yet — Fetch sitemap first").
* Confirmation dialogs for destructive actions list exactly what will be deleted (counts, labels).

## 5. Accessibility

Keyboard navigable, visible focus, colour is never the only signal (status badges have text/icons),
images have alt text (`before`, `after`, `diff` + URL).
