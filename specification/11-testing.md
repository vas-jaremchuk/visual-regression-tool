# 11 — Testing & acceptance

## 1. Test layers

| Layer | Tool | Scope |
|-------|------|-------|
| Unit | Vitest | `packages/engine` (all REQ-ENG), `shared` (schemas, crypto, r2-keys, HMAC), pure helpers in apps |
| Golden | Vitest + fixtures | filename parity (list of 200 real URLs from prototype sitemaps → expected names generated by running prototype code once and committing JSON), fingerprint text round-trip, pixel diff counts on fixture PNG pairs, static report snapshot |
| DB | Supabase local + pgTAP or Vitest with service/anon clients | RLS per role per table (matrix in 04 §3), RPCs, triggers |
| Worker | `wrangler dev` / vitest-pool-workers | HMAC verification, workflow step logic with fake `BrowserProvider`, queue consumer retry/idempotency |
| Container | Vitest + supertest | `/diff` with fixtures and fake object store |
| Web e2e | Playwright | login (magic link via Supabase Inbucket), create project, fetch sitemap (fixture server), start run (worker stubbed), report review flows, share link, permission denials |
| Smoke (staging) | Playwright, manual trigger | full real run against a small fixture site (≈ 10 pages, 1 PDF) on real Cloudflare |

## 2. Fixtures

* `fixtures/site/` — tiny static website served by a local server in tests: sitemap index → 2 child
  sitemaps, pages with lazy images, a cookie banner, an animation, a redirect, a 404, a PDF, a page
  protected by basic auth. A `v2/` variant changes one heading, one image, the PDF bytes, adds a page,
  removes a page.
* `fixtures/png/` — pairs: identical, 1-pixel change, height difference, antialias-only change.
* `fixtures/prototype-env/` — sample `.env` files for import tests.

## 3. Definition of done (every ticket)

1. Code + tests for the referenced REQ/F IDs; acceptance criteria in the issue all checked.
2. `pnpm lint && pnpm typecheck && pnpm test` green; e2e green if UI touched.
3. New env vars added to the zod schema **and** `.env.example`.
4. Migrations included, `supabase db reset` passes, generated types updated.
5. No secret or service key reachable from client bundles (CI check: grep build output).
6. Docs updated if behaviour deviates from spec (with justification in PR).

## 4. Release acceptance (v1)

Using the fixture site on staging:
1. Admin creates project via `.env` import, invites an editor and a viewer.
2. Editor fetches sitemap: redirect excluded, PDF classified as file, counts correct.
3. Editor runs capture for desktop + mobile; progress live; completes.
4. Site switched to `v2`; second run; comparison shows: heading change (changed), image change (changed), new page, missing page, PDF fingerprint changed, redirect listed.
5. Editor approves one, ignores one with region rule, re-diffs → ignored item unchanged; notifications delivered to email + Slack.
6. Viewer can open report but every mutating action is denied (UI hidden + API 403).
7. Share link opens without login, read-only; revoke → 404.
8. Legacy import of a real prototype bucket set; comparison legacy ↔ new desktop run works.
9. Delete run removes R2 objects and dependent comparisons; storage page reflects it.
